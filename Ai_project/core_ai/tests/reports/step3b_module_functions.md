# تقرير الخطوة 3ب: الدوال المستقلة (يلي برّا الكلاسات)

**التاريخ:** 2026-10-28
**ملف الاختبارات:** [`core_ai/tests/test_module_functions.py`](../test_module_functions.py)
**البيئة:** حاوية `ai_web` (Python 3.10.20، tree-sitter 0.20.4)

## المشكلة
قارئ ملفات بايثون كان يقرأ **بس الدوال يلي جوا كلاس**. أي دالة مكتوبة مباشرة بالملف (متل `def load(path):`) ما كانت تظهر أبداً، فالنظام ما كان يقارنها لا بالتوثيق ولا بنسختها القديمة. ونفس الشي بالجافاسكربت والتايبسكربت (`function f()` و `const f = () => ...`).

**قديش هالمشكلة كبيرة:**
- ببيانات DocPrism: **26 من 52** دالة مستقلة، يعني نص المجموعة ما كان ينفحص.
- بكود مشروعنا نفسه: **185 دالة بـ 40 ملف بايثون** ما كانت تنشاف.
- بواجهة مشروعنا (TypeScript): **58 دالة بـ 15 ملف من 23**.

## الحل
1. **قارئ الملفات بيجمع الدوال المستقلة بمفتاح جديد اسمه `module_functions`.** ما حطيناهم مع الكلاسات (`classes`)، لحتى **ما يتغيّر مخطط الكلاسات يلي بتعرضه الواجهة**.
2. **`ASTUnifier` بيحوّلهم لكلاس وهمي اسمه `<module>`**، فبينفحصوا بنفس الطريقة يلي بتنفحص فيها الدوال يلي جوا الكلاسات.
3. **الكلاس الوهمي مش كلاس حقيقي**، فما بيطلع عليه:
   - تنبيه "كلاس غير موثّق" بالكود مقابل التوثيق، وما بينحسب بنسبة الكلاسات الموثّقة.
   - "كلاس انحذف" أو "كلاس انضاف" بالكود مقابل الكود. إذا كانت كل الدوال المستقلة جديدة أو انحذفت، بتطلع كل دالة لحالها.
4. **بالجافاسكربت والتايبسكربت** صار يقرأ: `function f()`، و `export function f()`، و `export default function f()`، و `const f = () => ...`، و `const f = function ()`.
5. **اسم الدالة بدون الأنواع العامة:** `useRetry<T = any>` بيصير `useRetry`، لحتى ينطابق مع اسمها بالتوثيق.
