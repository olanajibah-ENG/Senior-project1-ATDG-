# تقرير الخطوة 5: إرسال الطلبات للموديل، قراءة الجواب، والفلترة

**التاريخ:** 2026-10-28
**ملف الاختبارات:** [`core_ai/tests/test_doc_semantic_analyzer.py`](../test_doc_semantic_analyzer.py)
**البيئة:** حاوية `ai_web` (Python 3.10.20)

## الهدف
بالخطوة 4 جهّزنا الطلب. بهالخطوة بنينا القطعة يلي **بتبعت الطلب للموديل، وبتقرأ جوابه، وبتنضّفه**، وبتطلّع تنبيهات جاهزة. وهاد هو الجزء التاني من طريقة DocPrism: **الفلترة الخارجية**، يعني فحوصات بالبرمجة بعد جواب الموديل.

| الملف | التغيير |
|---|---|
| `doc_semantic_analyzer.py` (جديد) | `DocSemanticAnalyzer`: الإرسال مع إعادة المحاولة، وقراءة الجواب، والفلترة، والإحصائيات |
| `doc_prompt_builder.py` | كل بند صار يحفظ أسطر الكود يلي انعرضت مع أرقامها، لحتى نتأكد من الأسطر يلي بيذكرها الموديل |

## كيف بتشتغل

**1. الإرسال:**
- إذا فشل الطلب (شبكة، أو جواب فاضي، أو JSON مكسور)، منعيد لحد 3 مرات.
- **إعادة المحاولة بتتجاوز الأجوبة المحفوظة**، وإلا بيرجعلنا نفس الجواب الفاشل.
- **إذا فشلت كل المحاولات:** النظام ما بيوقع. منسجّل الكلاس بقائمة `failed_classes`، والفحوصات القديمة البسيطة بتضل شغّالة بداله.

**2. تحويل الجواب لتنبيهات:**

| سؤال الموديل | التصنيف | الخطورة (للواجهة) |
|---|---|---|
| `conflicting` | Direct_Mismatch | high |
| `not_implemented` | Over_Promise | medium |
| `undocumented` | Under_Promise | low |

**3. الفلترة:**

| الفلتر | القاعدة |
|---|---|
| الوعد الناقص | بينحفظ بس ما بيتعرض (`is_flagged = False`) |
| النسخ من التوثيق | الجملة لازم تكون موجودة **بتوثيق هالدالة نفسها**، وإلا بتنرمى. بنتساهل بالمسافات، وعلامات Markdown، وحالة الأحرف، والاختصار بـ `...` |
| النسخ من الكود | أرقام الأسطر لازم تكون من الأسطر يلي انعرضت، والسطر المنسوخ لازم يكون موجود. بنتساهل إذا نسخ رقم السطر مع الكود |
| عتبة الثقة | المعروض بس يلي ثقته **0.7 أو أكتر**. والثقة بشكل نسبة مئوية (85) بتتحوّل لـ 0.85 |
| التكرار | نتيجة وحدة لكل دالة ونوع، والأعلى ثقة هي يلي بتضل |

**4. الإحصائيات:** عدد الطلبات والفاشل منها، وقديش نتيجة رجّع الموديل، وقديش انرمى ولأي سبب، وقديش انعرض. هالأرقام بتلزمنا بالتقرير لحتى نبيّن أثر كل فلتر.
