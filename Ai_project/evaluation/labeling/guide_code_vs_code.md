# دليل الوسم — Code vs Code (Structural / Behavioral)

**النسخة:** مسودة 0.1 — 2026-10-23
**ليش هالوسم مهم منهجياً:** تقسيم Structural / Behavioral **من وضعنا نحنا** — ولا AexPy ولا Safer Builders ولا NPM وسموا بياناتهم هيك. فإذا قيّمنا النظام على تصنيف مشتق من قواعده هو، بيصير التقييم مرآة مش اختبار.
لهيك الأسئلة هون **معرّفة بالسلوك الملاحَظ للمستدعي**، مش بآلية النظام (ما في ذكر لـ hash ولا Body ولا مصفوفة القرار). والشخص اللي بيوسم **ما لازم يكون شايف** قواعد الـ ChangeClassifier.

---

## 1. وحدة الوسم

كل سطر = **عنصر واحد تغيّر** (دالة، method، attribute، أو export) بين النسخة A والنسخة B.

قائمة العناصر المتغيرة بتطلع من **diff نصي محايد** (مش من مخرجات نظامنا)، وبتشوف لكل عنصر:
- نسخته بـ A ونسخته بـ B كاملة (توقيع + جسم + decorators).
- عنصر موجود بـ A بس (محذوف) أو بـ B بس (مضاف) بيتعرض لحاله.

## 2. ثلاث أسئلة مستقلة

جاوب على كل سؤال **لحاله** — جواب سؤال ما بيأثر على التاني.

### Q1 — `interface_changed`: هل تغيّرت الواجهة المعلنة؟
`1` إذا تغيّر أي شي من هدول:
- الاسم (rename)، أو العنصر انحذف / انضاف.
- الـ parameters: إضافة، حذف، ترتيب، اسم، نوع، **قيمة افتراضية**، نوع الـ parameter (positional / keyword / `*args` / `**kwargs`).
- نوع الإرجاع المعلن.
- نوع العنصر: دالة ↔ attribute / `@property` / `@staticmethod` / `@classmethod`.
- الـ export (JS/TS): `export default` ↔ named export، أو انشال من الـ exports.

`0` إذا التوقيع المعلن هو هو حرفياً (بغض النظر عن الجسم).

### Q2 — `behavior_changed`: هل تغيّر السلوك؟
فكّر باستدعاء **صالح بالنسختين** (نفس المدخلات بتشتغل بـ A وبـ B).
`1` إذا في استدعاء واحد على الأقل من هالنوع بيعطي فرق ملاحَظ:
- قيمة إرجاع مختلفة (حتى لحالة طرفية وحدة).
- استثناء مختلف، أو صار يرمي / بطّل يرمي.
- أثر جانبي مختلف (كتابة ملف، DB، شبكة، تعديل على المدخلات أو state).
- القيمة الافتراضية تغيّرت ← الاستدعاء بدونها بيعطي نتيجة تانية ← `1`.

`0` إذا كل استدعاء صالح بالنسختين بيعطي نفس النتيجة بالضبط. **هالحالات `0` حتى لو الجسم تغيّر نصياً:**
- إعادة هيكلة مكافئة (استخراج دالة مساعدة، إعادة تسمية متغير محلي، تبسيط شرط بنفس المنطق).
- تغيير تعليقات، docstring، تنسيق، type hints بدون أثر وقت التشغيل، أو logging.
- عنصر محذوف أو مضاف بالكامل ← ما في استدعاء صالح بالنسختين ← `0`، ويكفي `Q1 = 1`.

### Q3 — `breaks_existing_caller`: هل بينكسر مستدعي قديم صحيح؟
`1` إذا كود كان شغّال صح على A رح **يفشل أو يعطي نتيجة غلط** على B.
- إضافة parameter إجباري، حذف عنصر عام، تغيير نوع إرجاع بيستعمله المستدعي ← `1`.
- إضافة parameter اختياري بقيمة افتراضية بتحافظ على السلوك القديم ← `0`.
- عنصر خاص (`_name` بالبايثون، `private` بـ Java/TS): **جاوب عادي**، وحط `private = 1`. التخفيض بيصير بالتحليل، مش بالوسم.

## 3. التركيبات المتوقعة

| Q1 | Q2 | المعنى | مثال |
|---|---|---|---|
| 1 | 0 | تغيير بنيوي بس | rename، إضافة parameter اختياري ما بيغيّر شي |
| 1 | 1 | بنيوي + سلوكي | تغيير قيمة افتراضية؛ parameter جديد والجسم تغيّر منطقه |
| 0 | 1 | سلوكي بس (الأخطر) | نفس التوقيع، صار يرجّع `None` بدل ما يرمي |
| 0 | 0 | ما في تغيير حقيقي | refactor مكافئ، تعديل docstring |

## 4. أمثلة محلولة

**مثال A — `Q1=0, Q2=1, Q3=1`**
```python
# A
def find(self, k: str) -> int:
    return self.d[k]            # بيرمي KeyError
# B
def find(self, k: str) -> int:
    return self.d.get(k, -1)    # بيرجّع -1
```

**مثال B — `Q1=1, Q2=0, Q3=1`**
```python
# A
def fetchUser(self, uid): ...
# B   (نفس الجسم حرفياً)
def get_user(self, uid): ...
```

**مثال C — `Q1=0, Q2=0, Q3=0`**
```python
# A
def total(self):
    s = 0
    for x in self.items: s += x.price
    return s
# B
def total(self):
    """Sum of item prices."""
    return sum(x.price for x in self.items)
```
الجسم تغيّر نصياً والـ docstring انضاف، بس النتيجة نفسها لكل مدخل.

**مثال D — `Q1=1, Q2=1, Q3=1`**
```python
# A
def connect(self, timeout=30): ...
# B
def connect(self, timeout=5): ...
```

## 5. قواعد الحسم

1. **السلوك بيتحدد من الكود، مش من النية.** لا تعتمد على رسالة الـ commit ولا التعليقات.
2. **حالة طرفية وحدة بتكفي** لـ `Q2 = 1` (قائمة فاضية، `None`، رقم سالب).
3. **مش متأكد إذا التغيير مكافئ؟** حط `unsure = 1` واكتب الاستدعاء اللي عم تشك فيه. لا تخمّن.
4. **الدليل:** لـ `Q2 = 1` اكتب الاستدعاء المحدد اللي بيعطي فرق بعمود `evidence` (مثلاً: `find("x") مع d فاضي: KeyError ← -1`).

## 6. الإجراء

نفس إجراء دليل Code vs Doc:
1. **Pilot** على 10 عناصر ← نقاش ← نسخة 0.2 (ما بينحسبوا بالـ κ).
2. **وسم مستقل** من شخصين ← `labels_code_vs_code_<name>.csv`.
3. **κ لكل سؤال لحاله:**
   `python -m evaluation.labeling.kappa a.csv b.csv --column Q1 --column Q2 --column Q3`
   الهدف κ ≥ 0.60 لكل سؤال. أصعب سؤال متوقع هو Q2 (التكافؤ السلوكي) — إذا نزل عن 0.60 منحسّن قسم 2 ومنعيد.
4. **تحكيم** ← عمود نهائي منفصل، مع الاحتفاظ بالوسمين الأصليين.
