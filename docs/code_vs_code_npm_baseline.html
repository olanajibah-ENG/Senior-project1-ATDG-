أول نتائج Code vs Code على بيانات ورقة NPM

البيانات: 1460 تعديل بيكسر الكود، موسومين من مؤلفين الورقة. ومعهم 338 تعديل عادي جبناهم من نفس المشاريع، وهدول "سليمين على الأرجح" مش موسومين من المؤلفين.

القياس: بدون ذكاء اصطناعي، يعني الفحص البنيوي بس، وما كلّف ولا طلب. قسّمنا البيانات 20% تطوير و 80% اختبار.

"كشف" = Recall، و"السكوت عن السليم" = Specificity. وقسم التطوير طلّع نفس الصورة تقريباً.

شو بتعني هالأرقام

  1. النظام الحالي بيكشف أكتر بكتير من القديم: لقى 169 تعديل بيكسر ما كان القديم يشوفهم، وخسر 2 بس. والسبب الأساسي إنه صار يشوف الدوال يلي برّا الكلاسات، وهي كتير منتشرة بـ JavaScript و TypeScript.
  2. الثمن: 22 إنذار كاذب زيادة، فنزل "السكوت عن السليم" من 0.89 لـ 0.82.
  3. التغييرات السلوكية، وهي تقريباً ثلثين البيانات، ما بتنكشف فعلياً بدون ذكاء اصطناعي. يلي انكشف منها انكشف لأنه صادف في تغيير بنيوي بنفس التعديل. وهون بيبيّن ليش بدنا الخطوات 8 لـ 11.
  4. أكتر سبب للإنذارات الكاذبة: النظام بيعتبر أي تغيير بالتوقيع كسر، حتى لو كان إضافة معامل اختياري. وهاد بالزبط يلي بتصلّحه الخطوة 7.

ملاحظة صريحة للمناقشة

الـ Precision طالعة عالية (0.85 لـ 0.91)، بس هي مضخّمة لأنه 83% من العينات بتكسر الكود. فالرقم الأصدق للإنذارات الكاذبة هو "السكوت عن السليم". كمان 165 تعديل ما انفحصوا، لأنه كل ملفاتهم كانت اختبارات أو ملفات جديدة أو محذوفة.

الخطوة الجاية

بكرا ببداية اليوم، منقيس Code vs Code مع الذكاء الاصطناعي على عينة صغيرة من قسم التطوير، حوالي 25 تعديل. ومنختار تعديلات فيها ملفات قليلة، لأنه كل ملف بياخد طلب. وبعدها، إذا ضل وقت قبل السبت، منطبّق الخطوة 7.
