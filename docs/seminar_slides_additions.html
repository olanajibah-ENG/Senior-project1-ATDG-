06 · Inconsistency detection · Metrics

How we measure

MetricQuestion it answersFormula
PrecisionWhen we raise an alert, how often is it real?TP / (TP + FP)
RecallOf all real problems, how many did we catch?TP / (TP + FN)
SpecificityOf all correct cases, how many did we leave alone?TN / (TN + FP)
F1One number balancing precision and recall2·P·R / (P + R)
PFP (pair-wise fix precision, from CASCADE)Of the contradictions we caught, in how many does the alert disappear once the doc is fixed?caught pairs with a silent fixed version / caught pairs

Why PFP matters: CASCADE gives every contradiction together with its fixed version. An alert that stays after the fix was not about the contradiction. The old system scored PFP = 0: it flagged the broken and the fixed version alike.

Code vs Code on NPM uses the same Precision / Recall / Specificity, counted per commit.

06 · Inconsistency detection · Pipeline

How the detector works

Code vs Doc

1 · Parse codeAST: every function with body, parameters, return type
→
2 · Split docsEach doc section is matched to the function it describes
→
3 · Ask the AINumbered code + its doc; 3 questions: conflicting? not implemented? undocumented?
→
4 · FilterQuote must exist verbatim in doc and code; confidence ≥ 0.7; under-promise hidden
→
5 · AlertDirect mismatch or over-promise, with the doc sentence and code line as evidence

Code vs Code

1 · Parse both versionsAST of before and after, incl. top-level functions
→
2 · Structural diffRemoved, renamed, signature or field changes
→
3 · Semantic checkAI on the diagram (today: names only, not bodies)
→
4 · ReportBreaking / behaviour change with severity

Steps 8 → 11 will send function bodies (before and after) to step 3 of Code vs Code, as done for Code vs Doc.

3. شريحة المثال الحقيقي (حطّها بعد شريحة 16)

حالة حقيقية من CASCADE (مكتبة gson من Google). النظام نبّه على النسخة المتناقضة بثقة 1.0، ونسخ الجملة والسطر كما هم، ولما المطوّرين صلّحوا التوثيق، التنبيه راح. هاد بالزبط معنى الـ PFP.

06 · Code vs Doc · A real case from CASCADE

The alert follows the contradiction

com.google.gson.JsonPrimitive.getAsDouble()

public double getAsDouble() {
    return isNumber() ? getAsNumber().doubleValue() : Double.parseDouble(getAsString());
}
Original doc: alert raised 
@throws ClassCastException if the value
        contained is not a valid double.
Our system: Direct mismatch, confidence 1.0
“The doc says ClassCastException, but Double.parseDouble throws NumberFormatException.”
Evidence: the doc sentence + code line 3, both quoted verbatim and verified.
Fixed doc (real commit): no alert 
@throws NumberFormatException if the value
        contained is not a valid double.
Our system: silent. ✔
Old system: silent on both versions: it never saw the contradiction.

6 of the 11 contradictions we caught behave like this (PFP 0.55).

مثال احتياطي إذا بدكن تانيين، أو إذا انسألتوا عن مثال تاني: StopWatch.formatTime() من commons-lang. التوثيق بيقول "Returns the split time"، والكود بيرجّع getTime()، يعني الوقت الكلي. نبّه النظام بثقة 0.95، والتصليح الحقيقي شال كلمة "split"، فراح التنبيه.

06 · Inconsistency detection · Threats to validity

What these results do not show yet

  • Small dev samples: Code vs Doc on 25 CASCADE pairs (the paper uses all 71); Code vs Code with AI on 22 commits.
  • Held-out test splits not run with AI yet: CASCADE test needs 92 requests (≈ 2 days of free quota).
  • NPM safe commits are ours: 338 commits from the same projects with no breaking-change signal, not labelled by the paper’s authors.
  • One small free model (poolside/laguna-s-2.1); the papers used stronger models. Results may improve with a stronger one.
  • LLM-S has higher recall (0.54–0.67) than ours, at much lower specificity (0.42–0.58): our gain is fewer false alarms at good recall, not the highest recall.
